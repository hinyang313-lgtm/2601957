# 설계: 손글씨 인식 웹 버전과 데스크톱 버전 분리

작성일 2026-09-28

## 결정 기록

### 1. 추론을 어디서 수행할까

요청에 "외부 라이브러리 없이 순수 자바스크립트로 추론"이라고 적혀 있어 묻지 않고
정한다. 브라우저 안에서 자바스크립트로 순전파를 직접 계산한다. 서버도 없고
추론용 라이브러리도 없다.

### 2. 학습과 변환을 어디에 둘까

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| 가중치 내보내기 (채택) | 파이썬이 원본 하나로 남는다. 웹은 숫자만 읽으면 된다 | 순전파를 두 번 구현하게 된다 |
| ONNX로 변환 | 층 구조를 다시 쓰지 않아도 된다 | ONNX를 읽으려면 런타임 라이브러리가 필요하다. "외부 라이브러리 없이"와 어긋난다 |

**채택: 가중치 내보내기.** 학습과 변환은 `desktop_version/`에 둔다. 웹 버전은
학습하지 않는다. `가중치내보내기.py`가 `mnist_cnn.pt`를 읽어 `가중치.bin`과
`가중치정보.json`을 만든다.

### 3. 깃허브 페이지 배포를 범위에 넣을까

**넣는다.** `.github/workflows/pages.yml`이 `web_version/` 폴더만 배포한다.
저장소 맨 위에 `index.html`이 없으므로 Pages의 Source를 `GitHub Actions`로 둔다.

### 4. 웹 버전의 기능 범위

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| 데스크톱과 동일 + 터치 입력 (채택) | 두 버전을 나란히 비교하기 좋다. 만들 분량이 작다. 모바일에서도 쓸 수 있다 | 웹이라서 할 수 있는 것을 활용하지 않는다 |
| 28x28 전처리 미리보기 추가 | 전처리 단계를 눈으로 확인할 수 있다 | 데스크톱에 없는 기능이라 두 버전이 같지 않게 된다 |
| 숫자 10개 확률을 모두 표시 | 모델이 헷갈려 하는 숫자를 한눈에 본다 | 화면이 길어진다 |

**채택: 데스크톱과 동일 + 터치 입력.** 두 버전 비교가 목적이므로 기능 차이를 두지
않는다. 전처리 확인은 `검증.html`이 맡는다.

### 5. "외부 라이브러리 없이"의 범위

**실행 시점만 금지한다.** 브라우저가 내려받는 것 중에 우리가 쓴 파일이 아닌 것은
하나도 없어야 한다. 빌드 도구도 쓰지 않는다(빌드 단계 자체가 없다). 검증에 쓰는
파이썬 쪽 도구는 제한하지 않는다.

### 6. 정확성 검증 방법

**파이썬 결과와 대조하는 검증 페이지를 만든다.** 손으로 그려 보는 것만으로는
"무엇을 그려도 같은 답을 내는" 종류의 결함을 놓친다. `검증데이터만들기.py`가 정답
자료를 만들고 `검증.html`이 대조한다.

### 7. 가중치 파일 형식

**바이너리와 JSON으로 나눈다.** 숫자 42만 개를 JSON 텍스트로 담으면 파일이 서너 배
커지고 파싱도 느리다. 값은 `가중치.bin`(float32), 구조는 `가중치정보.json`에 둔다.

### 가중치 내보내기

텐서 8개를 정해진 순서로 float32 리틀 엔디언으로 이어 붙인다.
421,642개 × 4바이트 = 1,686,568바이트.

| 이름 | 형상 | 개수 |
| --- | --- | --- |
| 합성곱1.weight | 32 × 1 × 3 × 3 | 288 |
| 합성곱1.bias | 32 | 32 |
| 합성곱2.weight | 64 × 32 × 3 × 3 | 18,432 |
| 합성곱2.bias | 64 | 64 |
| 전결합1.weight | 128 × 3136 | 401,408 |
| 전결합1.bias | 128 | 128 |
| 전결합2.weight | 10 × 128 | 1,280 |
| 전결합2.bias | 10 | 10 |

정규화 상수 두 개(0.1307, 0.3081)는 `preprocess.py`에서 읽어 `가중치정보.json`에
같이 넣는다. 자바스크립트에 직접 적지 않고 이 파일에서 읽는다. 값의 출처를 파이썬
하나로 유지하기 위함이다.

### 자바스크립트 전처리와 순전파

- **순전파(`모델.js`)** — `model.py`의 층 구조(합성곱 2개, 풀링 2개, 전결합 2개,
  소프트맥스)를 자바스크립트로 다시 쓴다. 드롭아웃은 예측 시 아무 일도 하지 않으므로
  생략한다.
- **전처리(`전처리.js`)** — `preprocess.py`의 3단계를 그대로 옮긴다. 한 곳만 다르다.
  PIL의 LANCZOS 축소를 브라우저에서 재현할 수 없어 면적 평균 축소를 직접 구현한다.
  정확도가 떨어지면 그때 Lanczos를 구현한다.

순전파를 전처리보다 먼저 만든다. 순전파는 정답 자료의 28x28 입력만으로 검사할 수
있고, 전처리는 순전파까지 이어 붙여야 전체 정확도를 잴 수 있기 때문이다.

### 검증과 성공 기준

| 항목 | 기준 |
| --- | --- |
| 순전파 일치 | 같은 28x28 입력에 대한 확률의 최대 절대차 1e-4 이하 |
| 전체 정확도 | 확대 무리 200장 중 97% 이상 |
| 웹 앱 동작 | 그린 숫자를 인식하고 상위 3개 후보 표시 |

정답 자료를 구현보다 먼저 만든다. 검사 수단을 먼저 두고 그것을 통과하도록 구현하는
방식이다.

- 루트 — 두 버전의 관계와 공통 규칙(한글 식별자, 전처리 3단계)만 담는다
