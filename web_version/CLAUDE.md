# web_version — 순수 자바스크립트

외부 라이브러리를 하나도 쓰지 않는다. 브라우저가 기본으로 주는 것(`fetch`,
`Canvas 2D`, `Float32Array`, ES 모듈)만으로 전처리와 순전파를 모두 한다.
빌드 단계도 없다. 파일을 그대로 정적 호스팅에 올리면 된다.

## 로컬에서 여는 법

```bash
cd web_version
python3 -m http.server 8000
```

- 앱: <http://localhost:8000/>
- 검증: <http://localhost:8000/검증.html>

**`file://`로는 열리지 않는다.** HTML 파일을 두 번 눌러 열면 브라우저가 ES 모듈을
CORS로 막아 화면이 조용히 멈춘다. `index.html`과 `검증.html`에는 이 경우를 위한
안내 문단이 미리 들어 있고, 모듈이 실행되면 그 문단을 지운다. `onerror` 이벤트에
기대지 않는 이유는 `file://`에서 그 이벤트가 실제로 발화하는지 확인하지 못했기
때문이다.

## 파일

| 파일 | 하는 일 | 짝이 되는 파이썬 |
| --- | --- | --- |
| `index.html` | 앱 화면 | `desktop_version/app.py` |
| `스타일.css` | 화면 꾸미기 | — |
| `그림판.js` | 마우스와 터치로 그리기 | `app.py`의 Tkinter 캔버스 |
| `전처리.js` | 전처리 3단계와 정규화 | `preprocess.py` |
| `모델.js` | 순전파 | `model.py` |
| `앱.js` | 위 셋을 잇기 | `app.py`의 `인식()` |
| `검증.html` | 파이썬 결과와 대조 | `검증데이터만들기.py` |
| `가중치.bin` | 가중치 값 | `가중치내보내기.py`가 만든다 |
| `가중치정보.json` | 텐서 목록과 정규화 상수 | 〃 |

`그림판.js`와 `index.html`, `스타일.css`, `앱.js`는 Tkinter 코드를 옮긴 것이 아니라
새로 쓴 것이다. 기능만 같다.

## 가중치.bin 형식

`float32` 리틀 엔디언 값 421,642개를 이어 붙인 것이다(1,686,568바이트). 어느 값이
어디에 있는지는 `가중치정보.json`의 `텐서` 목록이 정한다.

```json
{ "이름": "합성곱1.weight", "형상": [32, 1, 3, 3], "시작": 0, "개수": 288 }
```

순서는 `가중치내보내기.py`의 `텐서순서`가 정하고, `모델.js`가 그대로 따른다.
한쪽만 바꾸면 조용히 틀린 답이 나온다.

`new Float32Array(버퍼)`는 길이가 4의 배수가 아니면 네이티브 `RangeError`를 던져
무슨 일인지 알기 어렵다. 그래서 `모델불러오기()`가 `byteLength % 4`를 먼저 검사한다.

## 파이썬과 맞춰야 할 지점

| 지점 | 맞추는 방법 |
| --- | --- |
| 텐서 순서 | `가중치정보.json`을 읽어 이름으로 찾는다 |
| 정규화 상수 | `가중치정보.json`에서 읽는다. 코드에 적지 않는다 |
| 반올림 | 양쪽 모두 `floor(값 + 0.5)`. 파이썬 `round()`는 0.5를 짝수로 보내고 자바스크립트 `Math.round()`는 위로 올려서, 그대로 두면 결과가 갈린다 |
| 캔버스 해상도 | 언제나 280x280. CSS로 크게 보여도 내부 해상도는 늘리지 않는다. 늘리면 펜 굵기와 숫자 크기의 비율이 달라져 데스크톱과 답이 어긋난다 |
| 펜 굵기 | 20, `lineCap`과 `lineJoin`은 `round` |

## 딱 한 곳만 다르다: 축소 방법

파이썬은 PIL의 `LANCZOS`로 줄이는데, 브라우저에서 그것을 그대로 재현할 수 없다.
그래서 `전처리.js`는 면적 평균 축소를 직접 구현했다. 28x28 중간 결과는 파이썬과
조금 다르고(가장자리에서는 크게 다를 수 있다), 최종 정답률은 같은 수준이 나온다.
정확도가 떨어지면 그때 Lanczos를 구현하기로 했는데, 아래 실측대로 떨어지지 않아
구현하지 않았다.

면적 평균 축소에서 원본 경계를 `Math.min`으로 자르는 부분은 없으면 안 된다.
부동소수점 때문에 `(번호 + 1) * 비율`이 원본 크기를 아주 조금 넘는 경우가 실제로
있다. 예를 들어 `19 * (21 / 19)`는 `21.000000000000004`다. 자르지 않으면 배열 밖을
읽어 결과가 조용히 망가진다.

## 검증 절차

```bash
cd ../desktop_version && python3 검증데이터만들기.py   # 정답 자료를 만들고
cd ../web_version && python3 -m http.server 8000      # 서버를 띄운 뒤
#  http://localhost:8000/검증.html 을 연다
```

| 검사 | 기준 | 실측 |
| --- | --- | --- |
| 순전파 일치 (같은 28x28 입력에 대한 확률의 최대 절대차) | 1e-4 이하 | 2.05e-7 |
| 전체 정확도 (확대 무리 200장) | 97% 이상 | 100.0% (200/200) |
| 빈 전처리 | 0건 | 0건 |
| 획 무리 정확도 (참고, 기준 없음) | — | 100.0% (25/25) |

`검증데이터.json`은 약 25MB라 깃에 넣지 않는다(`.gitignore`). 그래서 깃허브 페이지에
배포된 `검증.html`은 정답 자료를 찾지 못하고 안내 문구만 보여준다. 검증은 로컬에서
한다.

검증을 통과했다는 말은 "옳다"가 아니라 "시험해 본 범위 안에서는 옳다"는 뜻이다.
시험하지 못한 범위를 늘리고 싶으면 `검증데이터만들기.py`의 획 무리에 표본을 더한다.
