# desktop_version — 파이토치 + Tkinter

손글씨 인식의 원본이다. 여기서 모델을 정하고 학습하고, 웹 버전이 쓸 가중치와
검증 자료를 내보낸다.

## 환경

- 파이썬 3.9 이상
- `torch`, `torchvision`, `numpy`, `pillow`
- `tkinter` (데스크톱 앱을 실행할 때만 필요하다. macOS 기본 파이썬에는 들어 있고,
  리눅스에서는 `python3-tk`를 따로 깔아야 한다.)

```bash
pip3 install torch torchvision numpy pillow
```

## 실행은 이 폴더 안에서 한다

`train.py`와 `검증데이터만들기.py`가 자료 경로로 상대 경로 `data`를 쓴다.
다른 폴더에서 실행하면 MNIST를 엉뚱한 곳에 다시 받는다.

```bash
cd desktop_version
python3 train.py        # 학습, mnist_cnn.pt 저장
python3 app.py          # 그림판 앱
```

`app.py`와 `가중치내보내기.py`는 `__file__` 기준으로 경로를 잡으므로 어디서 실행해도
가중치 파일은 제대로 찾는다. 자료 경로만 상대 경로다. 코드를 고쳐 절대 경로로 바꾸는
대신 이 문서에 적어 둔다.

## 파일 4개의 연결 관계

```
model.py       손글씨분류기 (층 정의)
   ↑
train.py       MNIST로 학습 → mnist_cnn.pt
   ↑
app.py         Tkinter 그림판 → 전처리 → 모델 → 상위 3개 후보
   ↓
preprocess.py  전처리 3단계 + 정규화
```

- `model.py` — 합성곱 2개, 최대풀링 2개, 전결합 2개. 파라미터 421,642개(텐서 8개).
  드롭아웃은 학습에서만 동작한다. 그래서 웹 버전은 드롭아웃을 아예 빼고 구현했다.
- `train.py` — 약한 어파인 변형(회전 10도, 이동 10%, 확대축소 0.9~1.1배)을 준다.
  MNIST 시험 자료만 외우지 않고 사람이 마우스로 그린 숫자도 맞히게 하려는 것이다.
  시험 정확도가 가장 좋았던 에포크의 가중치만 저장한다.
- `preprocess.py` — 여백 자르기, 비율 유지 20x20 축소(LANCZOS), 무게중심 이동.
  `정규화_평균 = 0.1307`, `정규화_표준편차 = 0.3081`이 여기에 있다. 이 값의 출처는
  이 파일 하나다.
- `app.py` — 그림판은 280x280, 검은 바탕에 흰 펜, 굵기 20. 캔버스에 그리는 것과
  같은 내용을 PIL 그림으로도 들고 있고, 전처리는 PIL 그림 쪽을 쓴다.
  `획그리기()`는 `검증데이터만들기.py`도 가져다 쓴다. 화면이 없는 환경에서도
  임포트되도록 `tkinter` 임포트를 `try`로 감쌌다.

## 웹 버전을 위한 스크립트 2개

### 가중치내보내기.py

`mnist_cnn.pt` → `../web_version/가중치.bin`, `../web_version/가중치정보.json`

- 텐서 8개를 `텐서순서` 목록의 순서대로 float32 리틀 엔디언으로 이어 붙인다.
  이 순서를 바꾸면 `web_version/모델.js`도 함께 바꿔야 한다.
- 정규화 상수도 `가중치정보.json`에 같이 넣는다. 자바스크립트가 상수를 코드에
  적지 않게 하려는 것이다.
- 끝에서 바이트 수가 파라미터 수의 4배인지 확인한다(1,686,568 = 421,642 × 4).

### 검증데이터만들기.py

`../web_version/검증데이터.json`(약 25MB, 깃에 넣지 않는다)

표본을 두 무리로 만든다.

- **확대 무리 200장** — MNIST 시험 그림을 최근접 이웃으로 10배 확대해 280x280으로
  만든 것. 통과 기준(97% 이상)을 재는 무리다.
- **획 무리 25장** — `app.py`의 `획그리기()`로 PIL에 직접 획을 그린 것.

획 무리가 왜 필요한가. 확대 무리는 200장 전부 28x28을 정확히 10배로 키운 것이라
숫자의 바운딩 박스 변이 언제나 10의 배수다. 그래서 사람이 마우스로 그렸을 때만
생기는 상황(어중간한 크기, 안티에일리어싱된 부드러운 획 가장자리, 캔버스 가장자리에
닿는 획)을 한 번도 시험하지 못한다. 실제로 이 빈틈 때문에 무엇을 그려도 같은 답을
내놓는 결함이 검증을 그대로 통과한 적이 있다. 획 무리는 그 빈틈을 메운다.

표본마다 다음을 담는다.

| 열쇠 | 내용 |
| --- | --- |
| `그림base64` | 280x280 밝기 바이트를 그대로 base64로 (PNG가 아니다. 다시 그릴 때 값이 바뀌지 않게 하려는 것) |
| `파이썬전처리` | 전처리를 마친 28x28 값 784개 (0~1) |
| `파이썬확률` | 소프트맥스 확률 10개 |
| `정답` | MNIST 라벨 또는 그린 숫자 |

## 고칠 때 확인할 것

`model.py`나 `preprocess.py`를 고치면 다음을 모두 다시 해야 한다.

1. `python3 train.py` (층을 고쳤을 때)
2. `python3 가중치내보내기.py`
3. `python3 검증데이터만들기.py`
4. `web_version/검증.html`을 열어 모든 검사가 통과하는지 확인
5. `web_version/전처리.js` 또는 `web_version/모델.js`도 같이 고쳤는지 확인
